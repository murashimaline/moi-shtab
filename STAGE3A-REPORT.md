## Исправлено

- **R1:** обычное сохранение использует строгую проверку импорта. Нельзя сохранить ссылку на отсутствующего сотрудника, объект, инструмент или платёж, в том числе список workerIds. При отказе предыдущие байты базы и подтверждённая модель сохраняются. Удаление связанного сотрудника не удаляет табель, выплаты и историю; операция целиком отклоняется. Несвязанные записи удалять можно.
- Удаление инструмента с движениями больше не стирает движения каскадом. Инструмент остаётся вместе со всей историей.
- Проверка перед обычным JSON-экспортом не позволяет назвать повреждённую старую базу готовой резервной копией. Для неё доступна отдельная загрузка исходных байтов через панель восстановления. Автоматическое исправление старых связей не выполняется.
- **R7:** обратный период зарплаты отклоняется расчётом; интерфейс убирает старый результат и показывает причину; Excel-ведомость не скачивается. Равные даты и незаданные границы поддерживаются.
- **R8:** таблица финансов и Excel-файл выбирают объект по ID, включая объекты с одинаковым названием.
- **Число работников:** пустое ручное количество в записи работ больше не скрывает заполненный табель. Выбранные в работах ID и присутствующие по табелю объединяются без повторов внутри объекта. Для каждого объекта берётся большее из числа известных сотрудников и максимального ручного количества; показатели объектов суммируются. Правило указано в самом отчёте. Отсутствовавшие сотрудники табеля не прибавляются. Реальные записи не переписываются.

## Изучено, оставлено без миграции

**R4 — склад.** Журнал и Excel по-прежнему получают объект движения из текущей карточки инструмента. Смена объекта карточки переобозначает старые движения. Возврат не сопоставлен с выдачей конкретному человеку; метка «Списан» не уменьшает количество. Исправлено только опасное каскадное удаление. Следующий шаг требует согласовать события передачи между объектами/складами, остатки по держателям, правила отмены и неизменяемые реквизиты движений. Для старых движений нельзя достоверно восстановить объект из нынешней карточки. Требуется сверка и отдельно согласованный план миграции с внешней копией.

**R5 — закрытие периода.** protectClosedReports защищает подотчётные операции и связанные названия, но не фиксирует табель, все ставки, доходы и общий результат проекта. Старые смены без ratePerShift используют текущую ставку сотрудника. Предупреждения и ручное подтверждение ставок сохранены; исторические ставки не подставлялись автоматически. Закрытый авансовый отчёт нельзя трактовать как закрытую зарплату или закрытый проект.

**R6 — старые источники и дубли.** Неизвестный paymentSource не становится подотчётным автоматически. Возможные дубли остаются с предупреждением, без удаления и без самовольного пересчёта. Специальный импорт табеля остаётся подготовленным JSON за май–октябрь 2026 года со ставкой 6000. Универсальный Excel-импорт не реализовывался.

## Ограничения и дальнейшие риски

- Уже имеющиеся разорванные связи читаются без изменений, но строгая проверка блокирует новые сохранения до исправления на основе сверенных данных. Исходный файл можно скачать отдельно. Это намеренная защита; автоматического создания вымышленных сотрудников или удаления истории нет.
- Ручные количества работников не содержат личностей: точную уникальную численность по всем объектам восстановить из них нельзя. Один сотрудник на разных объектах может учитываться повторно; это явно указано в отчёте.
- localStorage, квота, очистка браузера и гонка строго одновременных вкладок остаются ограничениями. Внешнее облачное хранение не входит в эти исправления.
- На реальных телефонах, Safari и настольном Excel проверки не выполнялись. Production в этой работе не проверялся и не публиковался.

Пользовательские данные не открывались и не изменялись. Миграции, отправка ветки, PR, публикация production и слияние в main не выполнялись.
