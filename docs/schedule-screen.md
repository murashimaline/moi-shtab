# ГП-03/ВГ02/Д01 — экран графика, вариант А

Экран использует существующий план и введённые статусы. У каждой работы две подписанные дорожки. Факт, готовность и число завершений с опозданием показывают «Нет данных». Свободный текст журнала работ, дополнительные поля с похожими названиями и ручной ввод в XLSX источником экранного факта не служат.

## Данные и расчёты

`scheduleScreenRows()` строит модель чтения поверх исходных записей. Стадия получает объект от родителя в модели отображения. Сохранённые `objectId`, ID и дополнительные поля исходных записей сохраняются без изменений. Родитель со стадиями остаётся контекстом. Сводка считает каждую стадию и этап без стадий один раз, независимо от поиска и фильтра. Сумма пяти взаимоисключающих статусов равна числу работ.

Валидный уникальный ID стадии используется вместе с идентичностью родителя. Для старых стадий без ID и неоднозначных ID применяется временный адрес внутри текущего снимка. Ключи предназначены для чтения и открытия карточки, в JSON не сохраняются.

`scheduleGetState()` независимо возвращает статус, предупреждение о плановых датах и отклонение. Пустой или нераспознанный статус имеет приоритет над истёкшим сроком. Работа до планового конца и в день конца остаётся «В работе». Со следующего локального календарного дня появляется просрочка. Явная задержка сохраняет собственную причину. Завершение остаётся «Выполнено» с сообщением «Окончание неизвестно». Ошибочный плановый интервал не рисуется.

Дата оценки фиксируется на один расчёт и обновляется при открытии раздела, возвращении фокуса окна и переходе документа в видимое состояние. Начало календарного окна дату оценки не меняет. Календарные разности вычисляются по датам без локального времени суток.

## Интерфейс

На ПК метаданные расположены слева, календарь справа. На ширине до 900 px метаданные размещаются над дорожками. Горизонтальная позиция синхронизируется у оси и календарей строк. Название открывает native dialog с полным набором реквизитов и причиной отсутствия факта. Карточка поддерживает касание, Enter, Tab и Escape, возвращает фокус к исходной кнопке. Из неё доступен существующий редактор этапа, для стадии — редактор её родителя.

Поиск учитывает название родителя. Фильтр и сортировка работают с целой логической работой, обе дорожки остаются вместе. Родитель найденной стадии остаётся в выдаче для контекста. Состояние просмотра хранится в памяти вкладки. Работы вне календарного окна сохраняются в списке.

## Проверка и воспроизведение

Запустить `node --test tests/*.test.cjs`. Новые сценарии находятся в `tests/schedule-screen.test.cjs`.

`tests/browser-schedule-screen.cjs` использует отдельные синтетические профили и размеры 1440/1024/768/390/320 px. Проверяются стадии выбранного объекта, метрики, одинаковые названия, legacy ID, отсутствие фантомных фактов, фильтры, сортировка, календарь, касание, клавиатура, граница локальных суток, пустой график, ошибочный интервал и 501 работа на 90 дней. Результаты и снимки `vg02-screen-*.png` записываются в `BROWSER_OUTPUT` либо `.browser-results` и входят в CI-артефакт `synthetic-browser-results`.

Снимки до и после просмотра сравнивают raw JSON, предимпортную копию, db, подтверждённый снимок и статус DataStore. Перехватываются записи localStorage. Синтетический набор содержит историю, фото и дополнительные поля.

Нужно также выполнить весь существующий браузерный набор, `tests/check-schedule-exports.py` и `tests/check-finance-exports.py`. Экспорт ВГ01 сохраняет собственный `scheduleFlatRows()` и генератор XLSX. Настольный Excel проверяется отдельно от CI.

Времена отрисовки большого набора записываются вместе с версией браузера, ОС, CPU и шириной окна. Мобильная эмуляция не устанавливает производительность физического телефона.

## Границы

Новый источник факта, ввод процентов, миграции и изменение DataStore в этот выпуск не входят. Полная функциональность ВГ02 требует отдельного решения по варианту Б. КТ-Р05, гонка конкурентного сохранения нескольких вкладок, остаётся открытым риском. Просмотр графика не добавляет операций сохранения.

После CI реализацию проверяет АУДИТ, затем ПОЛИГОН проводит UX-приёмку. Слияние требует отдельного решения CPU 0.3.

## Результаты ЖЕЛЕЗА для CPU

25 ноября 2026 проверены 187 модульных сценариев, 11 браузерных наборов и экспортные проверки XLSX/XML/JSON. Новые 18 экранных сценариев прошли на пяти ширинах, включая эмулируемый сенсорный свайп. Один локальный запуск экспортного браузера был прерван ошибкой Edge ERR_NETWORK_IO_SUSPENDED до открытия страницы; повторный запуск завершился успешно.

В отдельном финальном запуске перестроение 501 работы на 90 дней заняло 209 мс при ширине 1440 px и 122 мс при ширине 390 px. Среда Windows, Node 24.22.3, Edge 158.0.4370.33, Intel Core i7-7Y75, 4 логических процессора. Это измерение JavaScript и синхронного layout внутри мобильной эмуляции на ПК.

Ядро XLSX ВГ01, scheduleFlatRows и обработчик сохранения плана сверены с контрольной базой побайтово. storage.js не изменялся. Настольный Excel и физические мобильные устройства в рамках этого выпуска отдельно не испытывались. КТ-Р05 остаётся открытым риском.
