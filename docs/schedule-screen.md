# ГП-03/ВГ02/Д01 — экран графика, вариант А

Экран использует существующий план и введённые статусы. У каждой работы две подписанные дорожки. Факт, готовность и число завершений с опозданием показывают «Нет данных». Свободный текст журнала работ, дополнительные поля с похожими названиями и ручной ввод в XLSX источником экранного факта не служат.

## Данные и расчёты

`scheduleScreenRows()` строит модель чтения поверх исходных записей. Стадия получает объект от родителя в модели отображения. Сохранённые `objectId`, ID и дополнительные поля исходных записей сохраняются без изменений. Родитель со стадиями остаётся контекстом. Сводка считает каждую стадию и этап без стадий один раз, независимо от поиска и фильтра. Сумма шести взаимоисключающих статусов равна числу работ.

Валидный уникальный ID стадии используется вместе с идентичностью родителя. Для старых стадий без ID и неоднозначных ID применяется временный адрес внутри текущего снимка. Ключи предназначены для чтения и открытия карточки, в JSON не сохраняются.

`scheduleGetState()` независимо возвращает статус, предупреждение о плановых датах и отклонение. Пустой или нераспознанный статус имеет приоритет над истёкшим сроком. Работа до планового конца и в день конца остаётся «В работе». Со следующего локального календарного дня появляется просрочка. Явная задержка сохраняет собственную причину. Завершение остаётся «Выполнено» с сообщением «Окончание неизвестно». Ошибочный плановый интервал не рисуется.

Дата оценки фиксируется на один расчёт и обновляется при открытии раздела, возвращении фокуса окна и переходе документа в видимое состояние. Начало календарного окна дату оценки не меняет. Календарные разности вычисляются по датам без локального времени суток.

## Интерфейс

На ПК метаданные расположены слева, календарь справа. На ширине до 900 px метаданные размещаются над дорожками. Горизонтальная позиция синхронизируется у оси и календарей строк. Название открывает native dialog с полным набором реквизитов и причиной отсутствия факта. Карточка поддерживает касание, Enter, Tab и Escape, возвращает фокус к актуальной кнопке по ключу работы; при исчезнувшей строке — в поиск. Из неё доступен существующий редактор этапа, для стадии — редактор её родителя.

Поиск учитывает название родителя. Фильтр и сортировка работают с целой логической работой, обе дорожки остаются вместе. Родитель найденной стадии остаётся в выдаче для контекста. Состояние просмотра хранится в памяти вкладки. Работы вне календарного окна сохраняются в списке.

## Проверка и воспроизведение

Запустить `node --test tests/*.test.cjs`. Новые сценарии находятся в `tests/schedule-screen.test.cjs`.

`tests/browser-schedule-screen.cjs` использует отдельные синтетические профили и размеры 1440/1024/768/390/320 px. Проверяются стадии выбранного объекта, метрики, одинаковые названия, legacy ID, отсутствие фантомных фактов, фильтры, сортировка, календарь, касание, клавиатура, граница локальных суток, пустой график, ошибочный интервал и 501 работа на 90 дней. Результаты и снимки `vg02-screen-*.png` записываются в `BROWSER_OUTPUT` либо `.browser-results` и входят в CI-артефакт `synthetic-browser-results`.

Снимки до и после просмотра сравнивают raw JSON, предимпортную копию, db, подтверждённый снимок и статус DataStore. Перехватываются записи localStorage. Синтетический набор содержит историю, фото и дополнительные поля.

Нужно также выполнить весь существующий браузерный набор, `tests/check-schedule-exports.py` и `tests/check-finance-exports.py`. Экспорт ВГ01 сохраняет собственный `scheduleFlatRows()` и генератор XLSX. Настольный Excel проверяется отдельно от CI.

Времена отрисовки большого набора записываются вместе с версией браузера, ОС, CPU и шириной окна. Мобильная эмуляция не устанавливает производительность физического телефона.

## Границы

Новый источник факта, ввод процентов, миграции и изменение DataStore в этот выпуск не входят. Полная функциональность ВГ02 требует отдельного решения по варианту Б. КТ-Р05, гонка конкурентного сохранения нескольких вкладок, остаётся открытым риском. Просмотр графика не добавляет операций сохранения.

После CI реализацию проверяет АУДИТ, затем ПОЛИГОН проводит UX-приёмку. Слияние требует отдельного решения CPU 0.3.

## Доработка Д02 после принятия КТ-СХ01

В существующую ветку интегрирован main 239b2895bf16ba77dc98ea59c4477bed7ab86524 обычным merge без переписывания истории. storage.js и безопасный обработчик сохранения графика взяты из принятого PR №23, без последующих изменений. Дополнительные свойства остаются непрозрачными данными, а не источником факта.

Явная «Задержка» — отдельная красная категория delayed до/в последний плановый день, без слова «Просрочено» и без количества дней. Позже планового конца — late, «Отмечена задержка · Просрочено +N дн.». Шесть категорий применены к строкам, карточке, фильтрам и общей сводке по листьям. При неверном плане «Задержка» сохраняется с предупреждением дат и без фиктивного N.

Дефект фокуса воспроизведён до исправления в настоящем Edge: после возвращения в окно событие focus перестраивало DOM, и Escape не фокусировал новую кнопку. Теперь обработчик close находит кнопку по устойчивому ключу в текущем DOM, с fallback в поиск для скрытой строки. Переход в редактор фокусирует название этапа. Для уникальных исторических строковых ID, включая пустую строку, ключи стадий устойчивы; для отсутствующих/неоднозначных ID сохраняется адрес внутри текущего снимка.

Браузерный регресс отключает принудительное удержание фокуса Playwright через CDP и переключает вкладки в headless CI; локальный дополнительный запуск BROWSER_HEADED=1 BROWSER_FOCUS_ONLY=1 переключает два отдельных видимых окна Edge (различные Browser.windowId). Проверяется доверенное событие isTrusted с фазой return; синтетический dispatchEvent не используется как доказательство исправления этого дефекта. На 1440 и 390 проверяются Escape, кнопка закрытия, исчезнувшая при фильтрации работа, сохранение сортировки/диапазона/горизонтальной позиции и отсутствие записей. Локальный контроль шести сценариев отдельных окон — настоящий headed Edge, 1440/390. Его JSON с windowId, isTrusted и SHA-256 реализации сохранён в docs/evidence/vg02-d02-native-focus.json и копируется в CI-артефакт как локальное свидетельство, отдельно от результатов CI. Физические мобильные устройства отдельно не испытывались.

Сохранение по кнопке карточки стадии проходит через принятый редактор родителя и настоящий DataStore; raw JSON, дополнительные вложенные поля, старые ID, история и backup сверяются после записи и полной перезагрузки. Отдельный сценарий воспроизводит три стадии без собственного objectId: три учитываемых листа, один контекстный родитель, правильный объект в каждой карточке и ни одной записи при чтении.

Контроль безопасности: экспорт ВГ01 и scheduleFlatRows не меняются. Общий регресс включает прежние тесты КТ-СХ01, проверки точных чисел и восстановления, старых ID/явных статусов, конфликтов и ошибок хранилища, финансов, зарплаты, склада, JSON/XLSX/Excel XML и stress. Скриншоты 1440/1024/768/390/320 и результаты производительности входят в CI-артефакт. Точные числа запусков и ссылки на CI фиксируются в отчёте PR на итоговом HEAD.

Настольный Excel и физические мобильные устройства отдельно в этой доработке не испытываются. Факт/проценты отсутствуют по варианту А. Риски КТ-Р05 и КТ-РК01 №24 остаются открытыми; №24 обязателен до production. Слияние PR №21, публикации и миграции запрещены до нового решения CPU.
