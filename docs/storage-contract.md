# Б0-03: DataStore и постоянные ссылки

Исходная версия: ce60c39e9fb8a276b17889b0636675efb9448380.
Это совместимый рефакторинг version 3, без миграций и новых хранилищ.

## DataStore

`ProrabkaStorage.createDataStore(storage, key, empty)` — явное имя существующего адаптера. `create` остаётся той же функцией для совместимости. Приложение передаёт обёртку localStorage и прежний ключ `moiShtab_v03`.

| Метод | Контракт |
|---|---|
| initial(), readSnapshot() | Независимый JSON-снимок подтверждённого состояния. Не запись и не автоматическое исправление старой базы |
| status() | blocked, conflict, error и точные исходные raw для аварийного экспорта. error относится к загрузке; ошибка commit возвращается в его результате |
| commit(candidate, {importing=false}) | Синхронный результат {ok,value,error?}; value всегда независимый снимок подтверждённого состояния |
| observe(event) | Прежняя обработка storage event; true означает конфликт. Подписка остаётся в UI |
| readPreviousBackup() | Точные байты ключа _before_import; null — отсутствует, пустая строка — существующее значение, ошибка чтения выбрасывается |
| capabilities() | Неизменяемые признаки backend, schemaVersion, synchronous, atomicPrimaryWrite, crossTabCompareAndSwap, fileTransactions |

Ожидаемое состояние для commit — сохранённый адаптером raw; перед записью сравнивается с диском. Отдельный числовой expectedRevision не вводится: он не заменяет сравнение содержимого и token. Последовательность getItem/compare/setItem не является межвкладочным CAS, что явно отражено в capabilities. Результат commit не Promise; переход к async требует отдельного PR.

Чтение использует прежнюю validate(...,{links:false}), включая прежние значения по умолчанию в памяти. Нормализованный снимок не записывается при загрузке. Ошибочная загрузка блокирует обычное сохранение, исходные байты доступны через status. Это не пустая рабочая база.

Сохраняются строгая валидация при записи, защита закрытых авансовых отчётов, запрет новых дублирующих зарплатных расходов, financeHistory и _revision. При импорте точные прежние байты записываются в _before_import до основного JSON. Ошибка этой записи блокирует импорт; ошибка основной записи может оставить обновлённую предимпортную копию, но не меняет основную базу. Эти два ключа не являются общей транзакцией.

## ID и связи

ID — существующие непустые строки из букв ASCII, цифр, дефиса и подчёркивания; уникальность в пределах коллекции. Никакого преобразования ID, сопоставления по имени, перенумерации или генерации новых ID при загрузке. Действующие генераторы приложения не меняются.

`reference(collection,id)` возвращает замороженную пару; проверяет коллекцию и синтаксис ID. `resolveReference(snapshot,ref)` ищет точное совпадение, возвращает запись снимка либо undefined. Результат разрешения — ссылка на запись переданного снимка, не отдельная копия. Сам снимок из DataStore изолирован от подтверждённой базы.

Типизированная пара существует только в коде. В JSON сохраняются прежние поля:

| Поле | Коллекция назначения | Проверка |
|---|---|---|
| objectId | objects | Если задано, должно разрешаться |
| workerId | workers | То же; обязательно для attendance/payments |
| itemId | warehouse | То же; обязательно для warehouseMovements |
| paymentId | payments | Если задано, должно разрешаться |
| workerIds[] | workers | Каждый ID должен разрешаться |

Эта таблица применяется ко всем существующим коллекциям по прежним правилам валидатора. Набор коллекций: objects, tasks, works, goals, workers, attendance, payments, expenses, schedule, income, accountable, warehouse, warehouseMovements, timesheetImports.

referenceTargets — замороженный общий словарь одиночных ссылок. Валидатор использует resolveReference с прежними исходными значениями; новый constructor reference не усиливает скрыто правила чтения/записи старых записей. Исторические снимки financeHistory не являются живыми связями. advanceReports имеет ключ месяца, importSourceKey — происхождение импорта, sourceKeys — связи исходных строк табеля; они не подменяются ID сущностей.

## FileStore: только будущий контракт

Реализации нет. receipts/photos остаются внутри JSON без преобразования.
Предлагаемые операции: capabilities, stageWrite(stream), verify, publish, openRead, stat, abandon, collectUnreferenced. Бизнес-код использует fileId/blobId, адаптер — физический адрес. Запись порциями, проверка сохранённых байтов, неизменяемые опубликованные файлы. Предметная ссылка фиксируется только после успешной публикации; сбой может оставить неиспользуемый файл, но не успешную ссылку на недописанный файл. Удаление учитывает все сохраняемые версии/поколения/копии и активные операции.

Выбор OPFS, IndexedDB, внешней папки, шифрования, больших резервных копий и миграций не входит в Б0-03. 15 ГБ — текущий общий объём, не лимит и не подтверждённая ёмкость браузера.

## Проверки

Все fixtures искусственные. `node --test tests/*.test.cjs` включает существующие расчёты, исторические ставки 9000/9000/6000, повторный импорт, закрытые отчёты и новые контрактные проверки. Браузерные сценарии запускаются на случайном localhost-порту в отдельном профиле с блокировкой внешних запросов. Проверяются формы, откат, импорт/экспорт и чтение предимпортной копии через DataStore. Production и Pages не используются.
