# КТ-СХ01 — сохранность полей графика, задача №22

Основа: main `b56d288b91716273faf45b891a8ea15f45270a06`. Исправление существующего редактора; PR №21 не изменяется.

## Причина и исправление

Раньше сохранение заменяло этап и стадии объектами только из полей формы. Теперь существующие записи копируются целиком; накладываются лишь изменения редактируемых полей относительно первоначального состояния формы. Неизменённые поля, пробелы, отсутствующие необязательные свойства, неизвестные статусы и вложенные дополнительные данные сохраняются по значению. Привязка объекта существующего этапа меняется только через доступное поле формы; контекст объекта не переносит этап автоматически.

Строки стадий связаны через WeakMap с конкретным снимком редактора и исходной стадией. Для существующего ID дополнительно проверяются допустимость, уникальность и неизменность. Для legacy без ID действует только внутрипамятная идентичность строки и позиция в неизменном снимке; эти сведения не экспортируются. Название не используется для сопоставления. Перестановка строк сохраняет их идентичность; явное удаление исключает только выбранную стадию. Дублирующиеся/повреждённые ID, чужая строка или подменённый ID приводят к отказу. Новая стадия получает криптографический ID через прежний allocator с контролем коллизий и не наследует дополнительные поля удалённых стадий.

Существующие проверки prepareFormRecord, formEdits, recordForEdit и DataStore не обходятся. При устаревшем снимке, удалении этапа, внешней записи или ошибке хранилища частичного сохранения нет. Черновик остаётся в форме при отказе DataStore.

## Обоснование точечного изменения storage.js

Приёмочный сценарий №1 задачи №22 прямо требует вложенный `extension` у этапа и стадии, а также числовой `progress`. Базовый валидатор отвергал вложенные дополнительные поля этапа и любое нестроковое значение стадии до открытия редактора. Для выполнения этого требования неизвестные JSON-свойства графика допускаются как непрозрачные данные. Проверки структуры, обязательных полей, дат, идентификатора этапа, связей, типов известных полей и строковых полей стадии сохранены; валидация остальных коллекций не изменена. Схема JSON v3 остаётся прежней, поля не добавляются автоматически, миграции нет.

Дополнительные actualStart, actualEnd, progress и extension сохраняются, но не становятся источником факта для экранного или Excel-графика. Экспорт ВГ01 и финансовые расчёты не изменены.

## Проверки и границы

- Unit: объединение только изменённых полей; legacy и исторические ID; перестановка/удаление; неоднозначные ID; подмена строки; вложенные данные через настоящий DataStore, JSON и повторное открытие; сохранение структурной валидации.
- Browser: настоящая форма и DataStore; raw JSON, память, предимпортная копия и повторное чтение; просмотр без записи; все поля формы; стадии с одинаковыми названиями; добавление/удаление; ошибки дат, идентичности, версии и сохранения; отсутствие неявного переназначения объекта; создание после сброса формы. Артефакты браузерного CI включают синтетический JSON и снимок редактора.
- Полный имеющийся unit/browser регресс, включая P3, ДИ01, табель, назначения ответственных, диагностику, безопасный JSON и Excel-экспорты, выполняется отдельно с точными результатами в отчёте PR.

Все испытания — на синтетических копиях. Межвкладочное конкурентное сохранение КТ-Р05 остаётся отдельным архитектурным риском; этот PR его не исправляет. Повреждённые/неоднозначные ID стадий не исправляются автоматически. Исправление предотвращает дальнейшую потерю полей, но не восстанавливает уже утраченные данные.

Merge, публикация, миграции и продолжение доработки PR №21 требуют следующего решения CPU после независимого аудита.
