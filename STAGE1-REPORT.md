# Этап 1: надёжное сохранение и восстановление

Основа: main, версия 0.9.7, коммит `174f320daa181d063d61224f90079bf39814371c`.
Рабочая ветка: `fix/stage1-reliable-storage`. Релиз и слияние не выполняются.

## Изменения

- `storage.js` хранит отдельный подтверждённый снимок. Кандидат клонируется и проверяется до единственной атомарной записи основного ключа. При отказе записи возвращается подтверждённое состояние; несохранённые изменения не остаются в `db`.
- Общие формы, журнал с фото, график, подотчётные операции, выплаты и склад очищаются только после успешного сохранения. Отказы записи не вызывают перерисовку, которая могла бы изменить поля формы. Существующие специализированные импорты используют тот же механизм.
- Ошибка `renderAll` после записи имеет отдельное сообщение: данные сохранены, требуется перезагрузка. Она не выдаётся за ошибку записи и не откатывает успешную операцию.
- Повреждённый JSON, неподдерживаемая версия и некорректная структура блокируют обычные записи. Закреплённая панель явно объясняет, что показанная пустая модель не является пустой базой. Исходный ключ не меняется; исходные байты можно скачать, затем восстановить проверенную копию через обычный импорт.
- Полный импорт проверяет записи, уникальность и безопасную форму идентификаторов, типы полей, реальные даты, числа, вложенные массивы, документы, стадии, строки сверки и ссылки на сотрудников, объекты и инструменты. Проверка выполняется до замены состояния. Неизвестные скалярные поля сохраняются.
- Перед полным импортом точные предыдущие байты записываются в `moiShtab_v03_before_import`. Если резервная или основная запись не удалась, основной ключ остаётся прежним. Последняя копия до импорта доступна отдельной кнопкой скачивания. После успешной записи ошибка отображения не считается неудачей импорта.
- Ревизия с уникальным токеном добавляется внутрь прежнего JSON. Перед записью сравниваются все исходные байты; событие `storage`, включая очистку хранилища, блокирует устаревшую вкладку. Автоматическая перезагрузка не уничтожает введённый пользователем текст.

## Совместимость

Ключ `moiShtab_v03` и `version: 3` сохранены. Старые базы без ревизии читаются, отсутствующие необязательные коллекции добавляются в памяти. Числа в строках и неизвестные скалярные поля, документы и происхождение табеля сохраняются. Формулы расчёта зарплаты и подотчётных остатков не изменялись.

При загрузке существующей базы допускаются ранее возникшие оборванные ссылки: автоматического удаления и исправления финансовой истории нет. Полный импорт требует корректных ссылок; старый экспорт с оборванными связями потребует исправления копии перед импортом. Неподдерживаемые версии не мигрируются по предположению.

## Проверки

Запуск: `node --test tests/storage.test.cjs` (Node.js 24, без установки зависимостей).

11 автоматических тестов: переполнение и повторная попытка; повреждённый/неподдерживаемый JSON; некорректные записи и связи; отказ записи импорта; конкуренция вкладок и очистка; совместимость старого JSON; настоящий обработчик общей формы; настоящий `save` при ошибке отрисовки; синтаксис всех встроенных скриптов; расчёты после восстановления; повтор специализированного импорта табеля без дублей.

Проверены начисление и удержания, сохранённая ставка, строковые числа, аванс из подотчётных и перенос денежного остатка через пустой месяц. Пример: зарплатный остаток 2350 ₽, входящий и конечный подотчётный остаток 4299,75 ₽ остаются прежними после сохранения/загрузки.

`git diff --check` проходит. GitHub Actions запускает эти тесты для PR в main и ничего не публикует.

## Ограничения и риски

- Проверки выполняются в Node с имитацией хранилища и обработчиков; полный браузерный проход, реальные квоты Safari/Android, камера и визуальная проверка интерфейса не выполнены.
- У localStorage нет атомарного compare-and-swap. Сравнение ревизий и событие storage выявляют устаревшие вкладки, но не гарантируют предотвращение двух строго одновременных записей между чтением и записью. Для такой гарантии нужен отдельный этап с асинхронной блокировкой/IndexedDB. Работать с базой следует в одной вкладке.
- Копия до импорта расходует дополнительную квоту. Если места для неё нет, импорт безопасно отменяется. Автоматического удаления этой копии нет; она заменяется перед следующим импортом.
- localStorage остаётся локальным хранилищем: очистка браузера удаляет и основную базу, и внутреннюю копию. Внешний JSON-экспорт остаётся необходимым.
- Проверка структуры строже прежней: необычные или испорченные старые записи могут потребовать ручного восстановления. Исходные данные сохраняются без автоматической перезаписи.
- Разрешение конфликтов, финансовые правила, архивирование и прочие этапы аудита не входят в эти изменения.

Слияние допускается только после отдельного согласия пользователя.
