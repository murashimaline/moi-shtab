# Этап 2 — табель, зарплата и недельные выплаты

Основа: актуальная main `09e42e299c00488bf17c28570acade2fce219449`. Ветка: `stage2-payroll-model`. Только draft PR, без слияния и публикации.

## Согласованные решения

1. Почасовая оплата: ставка за смену / 8 × часы.
2. Выплаты учитываются по фактической дате в общем лицевом счёте сотрудника. Январь сохраняет долг на конец января при февральской выплате. Привязка выплаты к месяцу начисления не требуется.
3. Старые смены без снимка ставки продолжают считаться по текущей ставке с явным предупреждением. Новые смены фиксируют ставку.
4. Добавлена ручная фиксация исторической ставки выбранной старой смены. После неё текущая ставка сотрудника на начисление этой смены не влияет.
5. Недельная выплата по умолчанию предлагает начисление выбранной недели после удержаний. Сумма редактируется. Недельные начисления, недельные выплаты и общий долг показаны отдельно.

## Расчёт и совместимость

- Новая полная смена = 1; половина = 0,5; отсутствие = 0. Количество смен в форме доступно только для чтения и синхронизируется со статусом. Почасовые часы должны быть >0 и ≤24; сменный эквивалент = часы / 8. Часы прочих статусов справочные, отсутствие сохраняет 0 часов.
- Отсутствие начисляет 0 даже для старой противоречивой строки с количеством смен 1. Половина даёт 0,5 ставки. Старые дробные записи без этих двух статусов сохраняют исходный множитель, включая импортированные многосменные строки. Старые почасовые строки с корректными часами используют согласованную формулу; без часов — прежний множитель с предупреждением, без восстановления часов по предположению.
- Новая ручная смена сохраняет ratePerShift. Редактирование сохраняет этот снимок; выбор другого сотрудника берёт его ставку. Перевод отсутствия в рабочую смену берёт текущую ставку на момент изменения. Неизвестная/нулевая ставка блокирует новую оплачиваемую смену.
- Старые смены без снимка ставки не мигрируются автоматически. Изменение текущей ставки может менять только такие старые начисления; интерфейс предупреждает об этом. Специализированный импорт больше не фиксирует текущую ставку в старых строках автоматически перед изменением ставки сотрудника. Его новые импортируемые строки сохраняют исходную ставку 6000, повтор остаётся идемпотентным.
- Ведомость показывает входящий долг, начисления/штрафы/удержания/выплаты периода, движение периода и конечный долг. Входящий = всё движение до начала периода. Конечный = входящий + движение периода. Отрицательный долг — переплата, переносимая дальше. Работают пустые месяцы, переход года и частичные периоды. История удалённого сотрудника включается отдельной строкой без восстановления записи сотрудника в базе.
- Пример: январское начисление 6000 оставляет январский долг 6000; февральская выплата 6000 даёт входящий долг 6000, движение февраля −6000 и конечный долг 0. Выплата 7000 даёт долг −1000 (переплату 1000), переносимый в март. Январь от февральской выплаты не меняется. FIFO и распределения выплат по месяцам начисления нет.
- Каждая исходная зарплатная сумма округляется до копеек, половина копейки — от нуля. Далее суммируются целые копейки. Проверены 1,005 → 1,01; 10,075 → 10,08; −1,005 → −1,01; две суммы 0,105 дают 0,22. Поля остаются в прежней схеме в рублях. Зарплатная часть финансового анализа использует такое же округление.
- Excel ведомости использует тот же расчёт и включает три показателя долга. Экспорт табеля содержит расчётный и исходный множители, сохранённую ставку, начисление и предупреждения. JSON сохраняет исходные поля и происхождение.

## Фиксация исторической ставки: UX

В строке табеля есть действие «Зафиксировать ставку». Отдельная форма показывает дату, сотрудника и статус, просит ставку и основание, показывает начисление до/после. Неизвестная ставка не подставляется по предположению. Допускается явно подтверждённая нулевая ставка, отмечаемая предупреждением о нуле.

Сохранение меняет только ставку выбранной записи и метаданные подтверждения: rateConfirmationReason, rateConfirmedAt, rateBeforeConfirmation. Дата, статус, смены, часы, штрафы, выплаты, исходный fingerprint и ключ импорта сохраняются. Это допускается также для импортированной строки; обычное редактирование её остальных полей блокируется. Повторный импорт не перезаписывает ручное уточнение. Самая первая ставка до подтверждения сохраняется; полноценного неизменяемого журнала всех последовательных правок этот этап не добавляет.

При отказе записи прежняя смена остаётся на диске и в памяти, введённые ставка и основание остаются в форме. После успешного сохранения и перезагрузки изменение текущей ставки сотрудника не меняет подтверждённую смену.

## Недельная выплата: UX

В разделе «Зарплата» отдельная форма «Выплатить зарплату за неделю»: дата внутри недели понедельник–воскресенье, один/все сотрудники, фактическая дата выплаты и источник средств.

Таблица отдельно показывает начислено за неделю, штрафы/удержания недели, после удержаний, авансы/выплаты за неделю по их фактическим датам и общий накопленный долг на выбранную дату выплаты. Недельные цифры могут включать даты позже даты выплаты — их охват явно подписан. Общий долг ограничен фактической датой, а не концом недели.

Начальная редактируемая сумма = начисление недели после удержаний (не меньше 0). Уже выданные деньги и старый долг автоматически не подменяют этот выбор; они показаны рядом для проверки. Пустая сумма или 0 пропускает сотрудника. Произвольная положительная сумма разрешена, в том числе ведущая к переплате. Сотрудники со спорными ставками получают предупреждение и в недельной таблице.

По кнопке создаются обычные операции «Выплата» с сотрудником, суммой, фактической датой и источником. Поля weeklyWeekStart/weeklyWeekEnd — метки защиты от повторного создания, а не распределение выплаты по месяцу начисления. Все выбранные выплаты сохраняются одним вызовом механизма этапа 1; при отказе частичных операций нет, суммы остаются для повторной попытки.

Повторная недельная выплата сотруднику за ту же неделю блокируется даже с другой датой/суммой; строка помечена и поле отключено. Для уточнения предлагается изменить существующую операцию в журнале зарплаты. Дополнительные выплаты можно оформить общей формой с проверкой дублей. При ручном редактировании недельной операции её метки сохраняются и проверяются.

## Дубли и конфликты

Совпадающее время смены одного сотрудника за дату, неуказанное время и отсутствие конфликтуют; смена объекта не обходит проверку. Отдельные день и ночь разрешены, но сумма известных часов >24 блокируется. Старые конфликты предупреждаются, автоматически не удаляются.

Одинаковые дата/сотрудник/вид/сумма выплаты блокируются как возможный дубль. Одинаковый штраф/удержание в табеле и зарплатной операции за дату блокируется с обеих сторон. Существующие повторы остаются в истории и расчёте с предупреждением: без сверки нельзя решить, какая запись правильная.

## Оставшиеся риски

Старые неизвестные ставки, часы и дубли требуют сверки. Итог с предупреждениями нельзя считать подтверждённым долгом. Проверка повторных удержаний эвристическая: разные даты/суммы и разбиение одного основания без устойчивого идентификатора не определяются. Независимые равные платежи за день могут быть заблокированы как подозрительные. Без времени начала/конца нельзя проверить точное пересечение дневной и ночной смены.

Расчёт начинается с первой доступной записи: неизвестный долг до начала истории не выдумывается. Отдельная операция возврата зарплатной переплаты, закрытие месяца, архив сотрудников и неизменяемый журнал корректировок не добавлялись. Журнал выплат сохраняет общий охват 0.9.7, хотя движение ведомости ограничено периодом. Для большого числа сотрудников недельная таблица может быть длинной. Safari/Android и настольный Excel не проверялись.

main, production, Pages, релиз и рабочие данные не менялись. Production проверена на `174f320daa181d063d61224f90079bf39814371c`. Draft не сливать и не публиковать.
